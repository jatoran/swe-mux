## Systemic pattern 1 — unsupervised background loops die permanently and silently

The single largest reliability theme, verified across four domains. Each of these loops
has **no exception guard**: the first uncaught exception kills the task for the remainder
of the daemon's (supervisor-preserved, potentially weeks-long) lifetime, with no log at
failure time, no health surfacing, and no restart. `observe_transcript` already has the
correct pattern (supervised restart with capped backoff, fault recorded, drained by
watchdog); none of the others do.

| Loop | Where | What silently stops | Verified kill vector |
|---|---|---|---|
| Fleet intelligence `_run` + `_consume` | `fleet_intelligence.py:217`, `:78` | stall/unattended/runaway/context-pressure/interlock/digest detection | `sessions.sessions[id]` bare index after an `await events.emit` suspension; server pops sessions concurrently (KeyError) |
| Provider quota poll | `provider_accounts.py:1339` | all quota/reset sampling for both providers | `_write()` sits outside the fetch try/except; `os.replace` raises `PermissionError` on a transient Windows lock |
| Telemetry event consumer | `operational_telemetry.py:462` | tool + compaction capture | try/**finally** with no except; sqlite errors re-raise through `run_sqlite_operation` |
| Telemetry hourly prune/reconcile | `operational_telemetry.py:474` | ALL retention enforcement + transcript reconciliation | bare `while True`; `reconcile_transcripts` catches only OSError/ValueError/JSONDecodeError, not sqlite3.Error |
| Rules-file watcher | `automation.py:748` | rules hot reload | TOCTOU stat race (unverified but evidence-cited) |
| Config watcher | `server.py:837` | config hot reload | `stat()` outside the try (unverified) |
| Process inspector, git monitor, media cleanup | various | process evidence, git status, media TTL | same pattern (unverified) |

**Fix direction:** one shared supervised-task wrapper (restart with capped backoff +
last-fault recorded + surfaced in `/api/diagnostics/status-health` or a sibling health
endpoint, mirroring `observer_restarts`). Apply to every long-lived loop. This also gives
the monitoring the roadmap's completion policy already promises ("every background poller
… has explicit bounds, cancellation, freshness, and diagnostics").

Related verified medium: **EventBus silently drops events** for a slow/dead subscriber
(`event_bus.py:99`, `except QueueFull: pass`, maxsize 1024, no counter) — this is both the
blinding mechanism after a consumer dies and an invisible capture-loss path under burst.
Add a per-subscriber drop counter + diagnostic.

## Systemic pattern 2 — session isolation / cross-attribution (verified)

The fixed cross-attribution bugs (sibling-cwd gate, agent_lifecycle_id anchor, native-id
guard) are present and sound on their original paths. But six adjacent paths still allow
one session's data or identity to affect another:

1. **HIGH — Quarantine resurrection on every restart** (`history.py:269`).
   `UPDATE history SET agent_visible=1 WHERE backend IN ('claude','codex')` runs inside
   `_migrate_schema` on **every** `HistoryIndex` connect (every daemon start/reload), not
   behind a one-shot column guard. `quarantine_misattributed_agent_run` sets
   `agent_visible=0` but leaves the row otherwise intact, so every misattributed run ever
   quarantined is resurrected into history queries after each restart. This silently
   regresses the already-fixed misattribution family. Fix: make the backfill one-shot
   (guard on schema version) and/or make quarantine a distinct column state the backfill
   cannot flip.

2. **HIGH — Transcript-switch retarget adopts non-mux CLI conversations**
   (`session.py:1977`). The sibling gate iterates only mux sessions; a plain-terminal
   `claude` run in the same cwd writing a fresh transcript within the 5s window can be
   adopted by an idle mux session, which then renders the foreign conversation's
   status/tokens under its own identity and permanently rekeys `native_session_id`.
   Two verified variants: the unpromoted-shell race (`_has_transcript_sibling` skips
   `backend == "shell"` sessions that have launched an agent but aren't promoted yet,
   `session.py:1951`) and the single-unclaimed-candidate adoption at first-observe
   (`session.py:1247`, adopts the sole unclaimed candidate even when it contradicts the
   `--session-id` native id known from spawn). Fix: require the candidate's session id to
   match the spawn-known native id when one exists; treat same-cwd live shells as blocking
   siblings; add a confirmation gate (e.g. candidate's first user message must match the
   session's own PTY-submitted prompt) before rekeying identity.

3. **HIGH — Exited-session root PID recycling** (`processes.py:673`). `_collect_session`
   walks the root by **raw PID** with no state or creation-time gate, and `_collect_all`
   iterates all manager sessions including retained exited ones whose `record.pid` is
   never cleared. A recycled PID re-attributes an unrelated process tree to the dead
   session, with interrupt/terminate actions offered on it. This is the one place the
   otherwise-honored PID+creation-time discipline is skipped. Fix: gate `_collect_session`
   on live state + verify root creation time against the recorded spawn time.

4. **HIGH — Stale `lastReply` cross-session copy** (`TerminalPane.tsx:382`). TerminalPane
   is reused unkeyed across stack-tab session switches; `lastReply` state has no reset on
   `session.id` change, so "Copy reply" can copy the previous session's reply after a
   switch. Fix: reset reply state on session-id change (or key the pane by session id).

5. **MEDIUM — Nested-Project git re-resolution bleed** (`project_files.py:436`). With a
   Project registered inside a larger worktree, notes/config/observations/spawn-config
   re-resolve to the enclosing git toplevel — wider than the documented notes-only gap.

6. **MEDIUM — Shim native-id capture misses `-r`/`-c`/`--continue`/valueless `--resume`**
   (`agent_launcher.py:52`). Live-probed: the CLI hard-rejects the injected
   `--continue --session-id <uuid>` pair (exit 1) unless `--fork-session`; a `-r <term>`
   search-term form can capture a non-uuid token as native id. Sibling of the fixed
   native-id family. Fix: parse all documented resume forms; never inject `--session-id`
   alongside continue/resume without fork.

Also verified in this family (medium): an explicit Project history scan can **reassign
`project_id` of mux-owned canonical rows** belonging to another (nested) Project
(`history.py:927`, no `external=1`/NULL-project guard, `ORDER BY external ASC` prefers
canonical rows), and startup reconcile **clobbers backfill-assigned project labels/roots**
on changed external rows (`history.py:820`).

## Systemic pattern 3 — status-detection residuals (verified, all medium/low)

The Phase 3.5 machinery held up well under audit (ledger total, watchdog pinned by
fixtures at thresholds, mobile parity single-sourced). Remaining verified holes, all in
the hook-spool and watchdog seams:

- **Hook-spool replay lacks identity/freshness/terminal-state guards** (`session.py:2042`,
  `:2160`, `hook_client.py:63`). Spool entries carry only `{event, payload}` — no
  timestamp, no run id; the drain runs before the terminal-state check; there is no
  exited/crashed latch in `apply_state_transition` (hook priority 2 outranks the pty
  priority 0 left by `_mark_ended`). Verified consequences: a spooled `SessionEnd`
  arriving after PTY EOF can resurrect a dead session to `idle`; a stale spooled `Stop`
  from turn N can force-idle live turn N+1; `demote()` never unlinks the spool so a
  leftover replays into the next promotion. Fix: stamp spool entries (ts + agent_run_id),
  drop stale/foreign entries at drain, add a terminal latch to `apply_state_transition`
  (only `daemon` source may leave exited/crashed), unlink spool on demote.
- **Watchdog stale-capture race** (`session.py:2047`): `stalled`/`pty_state` are captured
  before the `to_thread` tail read and reused after; an approval raised during the read
  is instantly `resume_working`-ed and not re-raised until the next hook. Fix: re-derive
  awaiting evidence after the await, or veto resume when `awaiting_since` postdates the
  capture.
- **PTY idle backstop unreachable exactly where promised** (partial, `session.py:2071`):
  missing/unreadable transcript returns early before any tail verdict, so the
  `force_idle_pty` recovery documented for wrong/missing-transcript cases cannot fire
  there; no fixture covers the missing-file branch.
- **No PTY marker for Codex questions/elicitations** (`session.py:456`): tail
  classification knows approval markers only; a stale "esc to interrupt" in the tail can
  let the resume path hide a real question (unverified scenario, cited evidence).

**User-reported item (notes line 57–59, "approved but still said awaiting approval"):**
the three-exit sticky-awaiting fix is present, fixture-pinned, and landed in the same
commit window (6964586, 07-26) as the note, so the observation almost certainly predates
the fix being deployed. If it recurs on the current build, capture
`GET /api/sessions/{sid}/state-log` immediately and promote it through the
capture-to-fixture pipeline. The watchdog stale-capture race above is the one verified
path that can still produce a related (reversed) misclassification.

**New status requested (owner, 2026-07-27): "ready but waiting on background work."**
A Claude Code session that ends its turn while background tasks/workflows run (PTY shows
`✻ Waiting for N … to finish`) renders as "ready - turn complete", which is technically
true (composer accepts input; delivery safe) but hides that the agent will self-resume.
Design sketch: an idle-axis sub-reason (mirroring `awaiting_reason`), e.g.
`idle_reason = waiting_on_background`, sourced from (a) PTY tail marker
(`Waiting for`/`background task`), (b) transcript tail (ScheduleWakeup / background-task
tool_use, task-notification records), (c) the signature "turn begins with no
UserPromptSubmit". Keep `delivery_state` unchanged; suppress/soften the turn-complete
sound and attention ping for this sub-state; verify a self-wake transitions back to
`working` cleanly without a user prompt (and add a fixture for that transition).

## Systemic pattern 4 — retention and durability gaps (verified)

- **HIGH — AutomationStore prune coverage**: `prune` touches only 4 tables and runs once
  at daemon startup (`server.py:630`); `automation_budget_ledger`,
  `automation_annotations`, `session_lineage`, `experience_entries`, `observer_batches`,
  `automation_checkpoints` have **no DELETE anywhere** — unbounded growth on a
  supervisor-preserved daemon. Fix: extend prune to all tables + run it in the (newly
  supervised) hourly loop alongside telemetry's.
- **HIGH — `/events` catch-up is broken end-to-end** (`server.py:5365` + frontend): the
  frontend never sends `after_seq`, and the server's no-cursor default replays the 2000
  **oldest** retained events (90-day/100k retention), so on every reconnect the client
  replays ancient events and the actually-missed recent ones are never delivered. Fix:
  frontend tracks and sends `after_seq`; server default should be "tail", not "head".
- **HIGH — `pty_ws` subscriber leak** (`server.py:5171`): any exception in the
  attach/replay window (mid-replay disconnect on a slow mobile link is the realistic one)
  skips the `finally` unsubscribe, permanently marking the session `attended` and leaking
  the queue. Sibling verified low: `events_ws` leaks on malformed `after_seq`
  (`int()` between subscribe and try, `server.py:5363`).
- **HIGH — PTY reader 5s cross-thread put timeout fabricates EOF**
  (`pty_host.py:197-209`): under 5s of consumer backpressure the uncaught `TimeoutError`
  reaches the finally, injects the `b""` sentinel with the reader thread dead; the
  supervisor treats `b""` as exit **without an `isalive()` check** and the removal path
  closes the nested Job — killing a live agent tree. Fix: catch the timeout and retry the
  put; require `isalive()` false (or exit status present) before treating sentinel as exit.
- **MEDIUM — transcript watermark/cache races**: `parse_transcript_cached` keys on
  `(path, mtime_ns, backend, max_bytes)` with **no size** — the only watermark in the
  codebase that doesn't pair mtime with size (Windows timer-tick mtime granularity makes
  same-stamp appends real); and `history_transcript` stamps the message-index watermark
  from a stat decoupled from the parsed content, and the poisoned watermark is trusted by
  every later `unchanged` check. Fix: add `st_size` to the cache key; derive the persisted
  watermark from the same stat the parse used.
- **MEDIUM — Claude sidechain records indexed as root messages**
  (`transcript_view.py:33`): no `isSidechain` filter on the index path (the live observer
  correctly special-cases them), so subagent chatter pollutes history search/results.
- **MEDIUM — layout snap-back + note-loss window** (frontend): `refresh()` overwrites
  optimistic layout state with no generation guard while `/events` traffic queues
  refreshes every 100ms during agent activity; and the pagehide beacon skips entries with
  a save in flight, dropping the newest pending note snapshot.
- **MEDIUM — dollar budget is soft**: cost reconciliation is a detached task that swallows
  `OpenRouterError` with no retry/log/marker, `stop()` cancels pending reconciles, and the
  price preflight is skipped when the model cache is empty. Token budgets and hourly caps
  are hard (verified). Fix if dollar bound should be trusted: request usage in-response,
  reconcile synchronously into the ledger, persist failed reconciles.
- Corrupt `mux.db` at startup crashes the daemon with no integrity check/quarantine/
  rebuild path; Tier0's `PRAGMA user_version=1` overwrites telemetry's `3` on the shared
  file each startup, disarming both stores' schema-version mechanism; AutomationStore has
  no migration mechanism and several stores use positional INSERTs that break on any
  future column addition (all verified as stated, medium).

## Appendix A — unverified single-pass findings

Evidence-cited by one domain auditor but not adversarially re-verified. Treat as
leads: confirm the cited code before acting. Sorted by severity.

- **MEDIUM/race** `src/swe_mux/automation.py:748` (automation-cp#6, likely) — Rules-file watcher dies permanently on a TOCTOU stat race, silently disabling hot reload
  - Scenario: An external editor (or agent) saves ~/.mux/rules.toml via delete+rename between the exists() check and stat(): FileNotFoundError (or a Windows sharing-violation OSError) propagates, the automation-watch task dies, and rule edits made directly to the file are never picked up again until daemon restart — with no diagnostic anywhere. server.py _watch_config (lines 834-837) repeats the identical pattern for the main config file.
  - Fix: Use a single try/except OSError around stat() (treating failure as 'unchanged'), move reload()'s trailing stat inside its try, and apply the same guard to _watch_config.
- **MEDIUM/monitoring-gap** `src/swe_mux/event_bus.py:99` (automation-cp#7, certain) — EventBus drops events for slow subscribers silently, blinding tier0/fleet/meta-hooks with no counter
  - Scenario: During an event burst (busy multi-session activity plus transcript reconciliation), a consumer that is briefly blocked on SQLite falls 1024 events behind; subsequent tool_use/tool_result/git events are silently discarded for that consumer — Tier 0 facts and fleet failure tracking are missing entries and nothing in /api/automation's queue diagnostics reflects it.
  - Fix: Track a per-subscriber drop counter in EventBus (keyed by a subscriber label) and surface it in the automation status payload alongside queue_dropped.
- **MEDIUM/bug** `src/swe_mux/voice.py:796` (config-spawn#2, likely) — STT timeout escapes the typed VoiceError boundary and races the finally-unlink against the still-running whisper thread, retaining the WAV
  - Scenario: A slow transcription (first-use model download, or CPU int8 fallback on a long utterance with beam_size=5) exceeds the 60 s wait_for. asyncio.to_thread cannot be cancelled, so the worker thread keeps transcribing with the WAV open. The finally unlink then (a) on Windows raises PermissionError (WinError 32) because the reader holds the file without FILE_SHARE_DELETE, masking the TimeoutError, and (b) leaves the utterance WAV in <data_dir>/voice/stt/ forever — there is no sweeper for that directory — violating the "audio is always deleted" contract. Either the PermissionError or the raw TimeoutError reaches voice_transcribe, which only catches VoiceError, so the client gets a 500 instead of the typed STT diagnostic.
