swe-mux ADE + ACP
mobile workbench control plane limits install
agentic dev environment + agent control plane

You can run ten coding agents.
You cannot watch ten coding agents.

swe-mux keeps every agent and terminal alive on your machine, and records what those agents actually did from the bytes they wrote and the exit codes they got, not from what they said about it.

Then it spends a hard budget of four interruptions a day on you. Everything else waits somewhere you can find it.

Windows 10/11 claude · codex · opencode · omp · pi · shell desktop, browser, phone PWA localhost and Tailscale only no account, no cloud

ADE / the workbench

Sessions, panes, tabs, notes, files, git, previews, a Run menu you define. Everything you look at. This part is table stakes, and every tool in the category has some of it.

ACP / the control plane

Deterministic evidence, model-free detectors, incident ranking, an interrupt budget, and a return path agents can read. Decides what you look at. Nobody else ships this.

swe-mux is both, and that is the point. The control plane is only buildable on top of the workbench: you cannot measure a fleet whose terminals, shells, and input telemetry you do not own.

03

The control plane

The agent CLIs are the data plane; they do the work. This layer observes, records, and routes attention without ever sitting in an agent's execution path. It never types, approves, spawns, or edits anything.

09 Attention inbox

Findings merge into incidents and route to one of four channels split by what they cost you: interrupt now, next breakpoint, inbox, digest. Four interrupts a day.

desktop crop

Inbox panel only. Must show the budget line (1/4 interrupts today), the fan-out reading, and at least one item held back with its visible suppressed reason. That last part is the whole argument.

mobile

04

Also in the box

  • History and searchOne row per conversation including the ones /clear retired. Full-text over prompts and replies, resumable. Native transcripts never modified.
  • VoiceLocal VAD, local Whisper, configurable wake word, spoken navigation by coordinate, reply playback you can talk over to stop.
  • Remote accessTailscale only. No swe-mux login, no port forwarding, no Funnel. Optional Serve for real HTTPS, which the mic and clipboard require.
  • Accounts and usageSaved provider accounts with one-click login switching and per-account quota windows. Optional historical cost analytics.
  • Process ownershipAttribution by PID plus creation time, unioned with job-object membership, so a detached grandchild is still yours.
  • DiagnosticsSupervised background loops, per-loop cost accounting, event-loop lag. mux doctor exports the whole picture.
05

What it will not do

  • Observers never act. The injection-safety endpoint always answers authorized: false.
  • Nothing runs on a project that did not opt in. No machine-wide automations.
  • Unknown fails closed. Readiness that cannot be established never authorizes input.
  • A summary is never the only copy. Every derived fact points back at its source.
  • Silence never reads as absence. Suppressed items are counted and shown with their reason.
  • Your provider setup is not touched. Transcripts, config, and skills stay where they are.
  • Nothing leaves the machine. No account, no cloud, no telemetry. Model calls only through your key, per project, against your budget.
  • It does not orchestrate. No roles, no lead agents, no task decomposition. Findings are advisory.
06

Not for you if

  • Not on WindowsConPTY and Win32 job objects. WSL is not a supported host.
  • You want an editorIt opens files and edits Markdown. No language server, no IDE ambitions.
  • You want a task boardSessions are long-lived processes, not tickets. Disposable worktree task cards are a different tool.
  • You want it hostedOne machine, one person, one data directory. No tenancy model.
  • You run one agentAlmost none of the control plane matters below about three concurrent sessions.
07

Install

Windows 10 or 11, uv, Node, WebView2 for desktop mode, and at least one agent CLI already installed and logged in. swe-mux does not manage the agent CLIs.

$ uv sync --extra desktop
$ npm --prefix frontend ci && npm --prefix frontend run build
$ uv run --extra desktop swe-mux

Desktop window plus a tray icon, daemon on 127.0.0.1:8765. Register a Project folder. Nothing spawns until you ask.
