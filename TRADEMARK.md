# Trademark policy

Apache-2.0 §6 grants no trademark rights. That is a reservation, not a policy:
it says the license does not give you permission to use the name, without saying
what would. This file says what would, so nobody has to guess.

## What is covered

The name **swe-mux**, the `swe-mux` and `muxd` command names, and the swe-mux
logo and tray icon.

## What you may do without asking

- Say that your software works with, integrates with, is built on, or is
  compatible with swe-mux. Nominative use - using the name to refer to this
  project - never needs permission.
- Redistribute swe-mux unmodified, under its own name, with this notice intact.
- Write about, review, teach, criticise, or fork the project and say plainly
  that your fork is a fork of swe-mux.
- Use the name in the title of an article, talk, video, or tutorial about
  swe-mux.

## What needs permission

- Naming a **modified** version "swe-mux", or naming a product in a way that
  suggests it is the official swe-mux, is published by this project, or is
  endorsed by it. A fork should carry its own name and may say it is derived
  from swe-mux.
- Using the name or logo as the primary brand of a commercial product or
  service, including a hosted or managed swe-mux offering.
- Using the logo in a way that implies partnership, sponsorship, or
  certification.

## Other people's trademarks

swe-mux launches and observes coding-agent CLIs published by other vendors,
including Anthropic's Claude Code and OpenAI's Codex CLI. Those names and marks
belong to those vendors.

**swe-mux is not affiliated with, endorsed by, sponsored by, or certified by
Anthropic, OpenAI, or any other vendor whose tools it can launch.** It uses
their names only to identify which tool a feature works with, which is
nominative use. Vendor logos are deliberately kept out of the project's own
branding and website.

## Asking

Open an issue. Requests that amount to "may I say my thing works with swe-mux"
are already answered yes above.
